### Integration sub-packages

- `internal/integration/cloudsync/` — S3 archive plane. Gitleaks secret scanning
  (`gitleaks.go`) + allowlist (`allowlist.go`) gate every push; `manifest.go`
  tracks synced content; `s3client.go` is the transport. Surfaced by `adb archive`.
  **`origin.go` is the credential boundary for the one artifact this package
  *synthesises*:** `repos-manifest.tsv` records each clone's
  `git remote get-url origin`, which for a clone configured as
  `https://user:TOKEN@host/o/r.git` is the token itself, uploaded verbatim.
  `StripOriginCredentials` removes the **userinfo component only** — not a
  blanket `RedactURL`, because `RepoEntry.Origin` must stay *re-cloneable*
  (`***` would make the column useless, which is the manifest's whole purpose):
  `RedactURL` would write `https://***@host/o/r.git`, which names the repo but
  cannot be cloned, whereas dropping the userinfo leaves a URL that can. The two
  functions **agree** on which bytes are the credential — since TASK-00039
  `RedactURL` drops a bare userinfo *username* too, so this note no longer rests
  on it under-redacting one — and differ only in what they leave behind. It is
  textual surgery, never a
  `net/url` round-trip: an scp-style `git@host:path` is not a parseable URL and
  `String()` can alter it, so anything without `://` passes through
  byte-identically, as does a URL with no userinfo. Over **http(s)** the whole
  userinfo goes (an https clone needs no username; the credential helper
  supplies it); over **ssh**/`git+ssh` the username survives and only a password
  is dropped, because there the username is a login identity —
  `ssh://github.com/o/r.git` does not clone. Idempotent, which is what lets
  `manifest.go` apply it at **both** the capture site (`GenerateManifest`, so no
  `RepoEntry` holds a token even in memory) and the render site
  (`FormatManifest`, which produces the uploaded bytes) — the same
  defence-in-depth shape as `stageFile`'s `os.Lstat` behind the walker's symlink
  skip. Before this the only thing between an embedded token and the bucket was
  the fail-closed gitleaks scan catching it in the staging copy: real mitigation,
  but *incidental* (it depended on staging order and aborted the push instead of
  fixing the URL).
- `internal/integration/issuesync/` — bidirectional GitHub/GitLab issue sync. A
  `provider.go` abstraction with `github.go` / `gitlab.go` backends, `mapping.go`
  (ticket↔issue), `reconcile.go`, and `select.go`. Surfaced by `adb issues sync`.

Notes worth carrying:

- **`sync` survives as a verb in exactly one place** — `adb issues sync` — because
  reconciling two authorities really is the operation. The others generate or publish in
  one direction.
- **`repos list` could not keep the name `list`.** The v3 `adb repo list` already means
  registered repositories from the control plane, not clones on disk; `inventory` exists
  because of that collision, not as a style choice.
- **`adb init claude` is deliberately NOT folded into `harness install`**, despite naming
  the same agent: it writes a stub at a target *path*, while `harness install` regenerates
  from live data into the agent's *config dir*. Different jobs, different argument shapes,
  and nothing replaces the former — so it stays put, by the same replacement test the
  `adb init` visibility rule uses.
- **The generated-file marker changed with `sync context`.** `internal/core/agentinstructions.go`'s
  `generatedMarker` names the regenerate command, and `IsADBGenerated` keys on it to decide
  whether a file is adb's to overwrite. Recognition is therefore the **union** of every
  marker ever written (`legacyGeneratedMarkers`) — drop one and every `AGENTS.md` adb wrote
  under that spelling silently reads as hand-written and is never regenerated again.
- `adb repo pull` / `adb repo inventory` are legacy children on the v3 `repo` parent, so
  like `org create` they carry **no** `v3Annotation` — that is what makes the root load the
  legacy `App` for them.

**Retired and re-homed in TASK-00039 (Q7) — the task vocabulary.** The same treatment
applied to `adb task`: the verbs were named for how they were *implemented* (`status` for
a listing, `cleanup` for a worktree removal, `delete` next to `archive`) and two top-level
nouns — `status` and `work` — described data that belongs to a task. Same alias mechanism,
same guarantee: every old spelling still runs and names its replacement on **stderr**.

| Retired | Now |
|---|---|
| `adb task status` | `adb task list` |
| `adb task status --git` | `adb task list --git` |
| `adb status` (top-level) | `adb task list --git` |
| `adb task delete <id> --yes` | `adb task remove <id> --yes` |
| `adb task priority <ids> --priority P0` | `adb task update <id> --priority P0` |
| `adb task unarchive <id>` | `adb task update <id> --status backlog` |
| `adb task cleanup <id>` | `adb task worktree remove <id>` |
| `adb work list\|switch\|prune\|reconcile` | `adb task worktree list\|switch\|prune\|reconcile` |

New in the same pass, adding no storage: `adb task show <id>` (the per-task read `list`
never was), `adb task close <id>` (`core.TaskManager.Close`, the method MCP's
`adb_task_close` also routes through), `adb task timeline <id>` (a view over
`.adb/events.jsonl` filtered by `data.task_id`).

Notes worth carrying:

- **`deprecatedAlias` builds an alias from the *target's* constructor**, which is what
  guarantees flag-set fidelity — and only works when the two spellings have the same
  shape. `task priority` → `task update --priority` and `task unarchive` →
  `task update --status backlog` are **merges** into a differently-shaped flag set
  (`priority` took `MinimumNArgs(1)` and a required `--priority`; `update` takes one id and
  four flags), so those two keep their own retired implementation and delegate to the same
  `core` method the new spelling calls. One implementation in `core`, two CLI entry points.
- **`adb task list --json` is always an array** — see the JSON-shape note under the
  `adb task` row. `adb status --json` and `adb task status --git --json` used to emit
  `{"tickets": …, "orphaned_worktrees": …}`; the alias keeps the *command* working, not the
  shape. The third shape moved the other way: `adb work list --json` emitted a **bare
  array** and now emits `{"worktrees": …, "orphaned": …}`, because the alias is built from
  the new constructor and orphans had nowhere to live in an array. Three incompatible
  shapes became two, each one now determined by its command rather than by a flag.
- **`task update --status archived` is rejected** and `--status backlog` on an archived
  task routes through `TaskManager.Unarchive`. See the `adb task` row.

> **`task migrate-types` was the only automated path for legacy `bug`-typed backlog
> rows.** The `bug` type is still rejected at create and still maps to a `fix/` branch
> for a pre-existing row, so nothing breaks — but retyping such a row is now a manual
> edit to `backlog.yaml` (the sole authoritative type store).

## Event schema (authoritative)

`internal/observability/schema.go` defines `KnownEventTypes` — the 19-element
contract every consumer (metrics, alerting, `adb events`, and `adb schedule add
--on-event`'s authoring gate)
relies on. Adding an event requires: declare the const, add it to
`KnownEventTypes`, and cover it in `TestKnownEventTypes_CoversEmittedSet`
(`schema_test.go`).

| Event type | Group | Notes |
|------------|-------|-------|
| `task.created` | task | payload: task_id, title, type, status, priority |
| `task.completed` | task | reserved |
| `task.status_changed` | task | old_status, new_status |
| `task.archived` | task | archived_at, archived_dir |
| `task.unarchived` | task | unarchived_at |
| `task.priority_changed` | task | old_priority, new_priority |
| `task.deleted` | task | deleted_at |
| `worktree.created` | worktree | task_id, path (emitted by TaskManager.Create for a repo-backed task) |
| `worktree.removed` | worktree | task_id, path, `reason`? — emitted by **every** removal path, all four in `TaskManager`: `task worktree remove` (`Cleanup`), `task archive`, `task remove` (`Delete`), and the sweeps `task worktree prune` / `reconcile --prune` (`RemoveOrphanWorktree`). The sweepers used to call `GitWorktreeManager.RemoveWorktree` straight from the CLI handler and log nothing, so `WorktreesRemoved` under-counted and #206's created/removed balance did not hold across a prune. **An orphan has no task to attribute the event to**, so its event carries an **empty `task_id`** plus `reason: "orphaned"` — additive, and safe by inspection: `adb task timeline` matches `data.task_id` by equality against a non-empty id (an orphan can never appear in a task's history), the metrics fold does not read `task_id` for worktree events, and `sessiondigest` already skips `""`. A distinct event type was rejected: the difference is provenance, not kind, and every existing consumer would have to learn a second name to stay correct |
| `knowledge.extracted` | knowledge | reserved |
| `agent.session_started` | agent | task_id, worktree, bin — emitted by `internal/cli/launch.go:launchWorkflow`, the one seam every `task create`/`start`/`resume` launch passes through (TASK-00039 moved it there from the removed `task run-with-ruflo`, which was its only producer) |
| `agent.session_active` | agent | heartbeat: task_id, worktree, activity. **Still has no producer** — declared for a live session to emit |
| `agent.session_ended` | agent | same keys + optional `error`. Emitted for a **failed** launch too: a session that could not start is the case most worth finding later |
| `issue.synced` | issue-sync | repo, provider, action, reason |
| `issue.conflict` | issue-sync | action?, reason?, error? |
| `issue.skipped` | issue-sync | repo |
| `stage.advanced` | stage | initiative_id, from, to, overridden (gate advance across Idea→MVP→Launch→Scale, #90/#137) |
| `stage.override` | stage | initiative_id, from, to, reason (human-only bypass of a blocked gate, #90) |
| `config.task_context_synced` | config | task_id, trigger (emitted by `adb task resume` when it re-renders a worktree's Tier-0 task-context.md, #155) |

> **Governance stream (D19/#137):** `stage.advanced` / `stage.override` are *also*
> mirrored to a **separate** append-only `.adb/governance.jsonl` (read via `adb governance`)
> so a compliance/audit reader sees governance decisions without the high-volume
> task/agent telemetry. Same two event types, written to a second sink — not new types.
> Separately, `adb archive`'s `cloud.sync_*` events remain declared locally and are
> **not** in `KnownEventTypes` (see L300/L400).
